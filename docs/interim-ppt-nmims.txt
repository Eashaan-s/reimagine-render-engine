SLIDE 4 — PROJECT OVERVIEW AND RECAP
================================================================================
Title: Project Overview and Recap

• Problem: Photoreal architectural visualization normally needs 3D modelling, materials, lighting, and long render times, while early design still lives in 2D wireframes and drawings.

• Proposed Solution: A Windows desktop application that takes a drawing, an optional style photograph, and a short instruction, then builds a standard image-to-image (I2I) edit job in one window — without a node editor and without training a new neural network.

• Expected System Outcome: A photorealistic preview appears in the Output panel; the user can export a PNG. Geometry of the drawing should be preserved while materials and lighting follow the prompt and style image.

Core Idea:
“Reconnaissance of the design from a drawing — photoreal preview from the same 2D sheet, in a single desktop client.”

(Shorter spoken line: Wireframe in, photoreal out, instruction in the middle.)

SLIDE 5 — LITERATURE SURVEY SUMMARY (table like the sample)
================================================================================
Title: Literature Survey Summary

Research Area | Key Focus / Findings | Identified Gap / Relevance

Image-to-image translation (GANs) [1–2]
pix2pix learns paired pixel-to-pixel maps (edges/labels → photo) with a cGAN; CycleGAN relaxes pairing via cycle consistency.
Defines the problem as I2I, not blank-canvas T2I. Pairing cost and blur/averaging limit a from-scratch GAN for this capstone.

Diffusion foundations [3–5]
DDPM: iterative denoising. Latent diffusion: denoise in a VAE latent. DiT/MMDiT: transformer denoisers at scale.
Explains GPU cost and modern backbones. These papers generate/edit images; they are not a designer-facing desktop workflow.

Spatial control and instruction editing [6–10]
ControlNet: edge/depth/pose on a frozen T2I model. InstructPix2Pix: edits from a written instruction. SDEdit / Prompt-to-Prompt: training-free or attention-based edits. Palette: diffusion I2I.
Same goals (keep structure, follow instructions). Gap: no simple drawing + style + prompt desktop job for architecture students.

Foundation models and PEFT [11–14]
LoRA: low-rank adapters (few-step “Lightning” sampling). SDXL: strong U-Net T2I baseline. Qwen2.5-VL + Qwen-Image: VLM semantics + VAE appearance + MMDiT editing.
Closest stack to the frozen graph we map. We cite and integrate; we do not train these models.

Architectural genAI and evaluation [15–18]
Reviews place genAI in concept images vs plans/BIM. Yeh et al.: architects need intent, realism, and variety — not FID alone. SSIM / LPIPS: structure vs perceptual appearance.
Gap we address: a usable client that packages I2I for concept preview, with honest evaluation later.

SLIDE 8 — METHODOLOGY
================================================================================
Title: Methodology

• Desktop client: Electron hosts the renderer; preload exposes generateRender, exportImage, getConfig, windowControl.

• Capture: User imports a drawing (required) and optional style photo; chips and textarea form one instruction (assemblePrompt).

• Mapping: buildWorkflowPayload fills node 370 (base), 371 (style), 377 (prompt), 368 (sampler: steps, CFG, name, seed). Defaults: 4 steps, CFG 1.0, Euler, random seed.

• Job package: JSON with workflow + images named reimagine_base.png / reimagine_style.png (base64).

• Inference (remaining): GPU worker executes the edit model (Qwen image-edit family) and returns a PNG.

• Visualization: Output panel, Export to Pictures / Reimagine Renders, history strip.

SLIDE 17 — CONCLUSION
================================================================================
Title: Conclusion

• Literature treats drawing-to-photo as I2I (GANs then diffusion), with ControlNet / instruction editors as control mechanisms, and Qwen-Image as a current edit foundation.

• Existing tools are node graphs or research code, not a three-column designer client.

• This project maps a desktop UI onto a frozen graph (370 / 371 / 377 / 368) and assembles a complete job package.

• Interim progress: 30% shell, 50% mapping, 70% client path; Inference worker is the next implementation stage.

• Scope remains concept visualization, not BIM or construction drawings. Models are cited, not retrained.
